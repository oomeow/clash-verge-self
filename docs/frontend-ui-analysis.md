# Clash Verge Self 前端界面功能分析

## 1. 目标与范围

本文面向 UI 重设计，聚焦 `src/` 下前端界面的信息架构、页面功能、关键交互、全局状态入口和设计约束，不讨论 Rust/Tauri 后端实现细节。

前端技术栈：

- React 19
- TanStack Router
- MUI + TailwindCSS
- Zustand
- Tauri Desktop Shell

## 2. 整体信息架构

应用采用桌面端双栏结构：

- 左侧为固定导航侧边栏
- 右侧为页面内容区
- 页面切换使用懒加载和预加载
- 全局悬浮层包括通知、拖放导入、弹窗、加载态

一级导航共 7 个业务页：

1. 代理 `Proxies`
2. 订阅 `Profiles`
3. 连接 `Connections`
4. 规则 `Rules`
5. 日志 `Logs`
6. 测试 `Test`
7. 设置 `Settings`

全局布局特征：

- 支持自定义标题栏/系统标题栏切换
- 支持窗口最大化、隐藏到后台、关闭行为差异
- 侧边栏在窄宽度下自动折叠
- 侧边栏底部长期展示实时流量/内存信息
- 路由首次进入有页面级 loading 覆盖层
- 全局支持拖放 YAML 文件导入订阅

## 3. 全局界面层

### 3.1 侧边栏

来源：`src/routes/__root.tsx`、`src/components/layout/sidebar.tsx`

功能：

- 展示一级导航入口与图标
- 高亮当前页面
- 鼠标悬停与空闲时预加载路由
- 小窗宽度下折叠为仅图标模式
- 底部嵌入流量与内存面板

对重设计的意义：

- 这是整个产品的主信息架构入口
- 导航可进一步强化“状态感”，例如当前代理模式、订阅数量、更新提醒、日志状态

### 3.2 顶层窗口控制

来源：`src/pages/_layout.tsx`、`src/components/layout/layout-control.tsx`

功能：

- 非系统标题栏时提供最小化/最大化/关闭
- 关闭时根据设置决定“隐藏窗口”或“真正退出”
- Linux/Windows/macOS 有不同表现

设计约束：

- 这是桌面应用，不是纯网页
- 标题栏、拖拽区域、窗口控制按钮需要保留桌面语义

### 3.3 全局通知

来源：`notistack` + `NoticeProvider` + Tauri event `verge://notice-message`

功能：

- 成功/错误/警告/信息提示
- 部分消息来自后端事件
- 多语言翻译后显示

### 3.4 全局拖放导入

来源：`src/components/layout/drag-import-overlay.tsx`

功能：

- 在任意页面拖入 `.yaml/.yml` 文件
- 全屏显示导入遮罩层
- 区分可导入文件与非法文件
- 成功后自动跳转到订阅页

对重设计的意义：

- 这是一个强入口操作
- 适合做成更明显的“导入工作流”而不只是覆盖层提示

### 3.5 实时状态卡

来源：`src/components/layout/layout-traffic.tsx`

功能：

- 实时上传/下载速度
- 可选流量曲线图
- 可选内存占用
- 点击内存图标可重启 Mihomo Core

对重设计的意义：

- 当前它被塞在侧边栏底部，本质上是全局运行状态面板
- 可考虑升级为状态中心、迷你仪表盘或顶部 status rail

## 4. 页面功能拆解

### 4.1 代理页 Proxies

来源：`src/pages/proxies.tsx`、`src/components/proxy/*`

定位：

- 这是代理切换与节点选择主界面

核心功能：

- 切换代理模式：`rule / global / direct`
- 展示代理分组列表
- 展开/折叠每个分组
- 查看当前分组选中的节点
- 选择节点并写回当前 profile 的 selected 状态
- `URLTest` 分组支持 fixed/unfixed 行为
- 切换节点后可自动关闭受影响连接

分组级交互：

- 一键定位到当前选中节点
- 一键批量延迟测试
- 切换排序方式：默认 / 延迟 / 名称
- 切换显示密度：基础 / 详细
- 输入过滤条件
- 自定义延迟测试 URL

列表表现：

- 使用虚拟列表
- 支持分组吸顶
- Rule 模式右侧有快速分组索引条
- 节点支持详细信息标签：类型、Provider、UDP、XUDP、TFO、延迟
- 分组支持远程图标缓存加载

设计重点：

- 这是高频操作页，优先级最高
- 当前功能密度很高，适合重构为“概览 + 分组详情 + 节点详情”的层级化布局
- 需要平衡快速切换、延迟数据、可读性和滚动效率

### 4.2 订阅页 Profiles

来源：`src/pages/profiles.tsx`、`src/components/profile/*`

定位：

- 管理配置来源、订阅文件、增强链、脚本链的主入口

核心功能：

- 输入 URL 导入远程订阅
- 从剪贴板粘贴订阅地址
- 新建 profile
- 查看运行时配置
- 一键更新所有远程订阅
- 一键重新激活配置链

主列表功能：

- 展示普通 profile 卡片
- 选择当前启用 profile
- 删除 profile
- 拖拽排序
- 展示描述、更新时间、到期信息、来源信息
- 对远程订阅执行单项更新

增强链区域：

- 独立展示全局 `merge / script` 项
- 开关启用/禁用链
- 删除链
- 拖拽排序
- 调整启用顺序后可触发重新激活
- 展示运行日志和脚本状态

弹窗/编辑能力：

- `ProfileViewer`：新建/编辑 profile 元信息
- 类型覆盖：`remote / local / merge / script`
- `ProfileEditor` / `ProfileEditorViewer`：编辑 YAML / JavaScript 内容
- Script 支持运行检查、日志查看、错误反馈
- 每个 profile 可挂载 profile 级 chain

设计重点：

- 这里其实混合了“资源管理”“配置编辑”“增强链编排”“脚本调试”四种任务
- 适合拆分为更清晰的信息层级，否则认知负担较大
- 对设计而言，普通 profile 与 chain/script 应明确视觉分层

### 4.3 连接页 Connections

来源：`src/pages/connections.tsx`、`src/components/connection/*`

定位：

- 实时查看连接流量与关闭连接

核心功能：

- 统计总上传/总下载
- 查看活动连接与已关闭连接两个 tab
- 支持列表视图与表格视图切换
- 支持关闭全部连接
- 活动页可按筛选结果批量关闭

筛选与排序：

- Host 搜索
- 多维过滤器
- 排序方式：默认 / 上传速度 / 下载速度

表格视图能力：

- TanStack Table
- 虚拟滚动
- 列排序
- 列宽拖拽调整
- 列显隐控制
- 列顺序拖拽
- 表格配置持久化

详情能力：

- 打开连接详情弹窗
- 查看链路、规则、上传下载总量、实时速度等
- 支持单条关闭连接

设计重点：

- 这是典型“运维监控页”
- 当前同时兼顾数据表与卡片浏览，重设计时建议明确主场景是“诊断”还是“管理”

### 4.4 规则页 Rules

来源：`src/pages/rules.tsx`、`src/components/rule/*`

定位：

- 查看运行中的规则与 Rule Provider 内容

核心功能：

- 拉取规则列表
- 拉取 RuleSet payload 内容
- 搜索规则
- 统计搜索结果
- 展开全部 / 收起全部
- Provider 操作入口

搜索特征：

- 支持基于文本、域名等方式搜索
- RuleSet 命中后可展示匹配的 payload 子项

设计重点：

- 当前偏“技术文本检索界面”
- 重设计时要考虑长文本可读性、展开层级、命中高亮与检索反馈

### 4.5 日志页 Logs

来源：`src/pages/logs.tsx`、`src/components/log/*`

定位：

- 实时查看内核日志

核心功能：

- 暂停/继续日志流
- 清空日志
- 日志级别过滤
- 文本搜索
- 虚拟列表展示

设计重点：

- 适合强调扫描效率、级别颜色系统、复制与定位能力
- 如果重设计覆盖深度足够，可以考虑增加结构化过滤和时间轴感

### 4.6 测试页 Test

来源：`src/pages/test.tsx`、`src/components/test/*`

定位：

- 管理可测试的网站列表并执行批量测试

核心功能：

- 默认内置 Apple / GitHub / Google / Youtube
- 新增测试项
- 编辑测试项
- 删除测试项
- 拖拽排序
- 触发全部测试

设计重点：

- 这是工具页，信息量不大
- 可以做得更轻量，也可以融入更强的网络诊断叙事

### 4.7 设置页 Settings

来源：`src/pages/settings.tsx`、`src/components/setting/*`

定位：

- 产品的配置中心，内容最复杂

结构：

- `System`
- `Clash`

功能：

- 系统代理总开关

系统代理弹窗 `SysproxyViewer` 还包含：

- 当前代理状态
- 服务地址
- PAC URL / PAC 内容
- 是否启用 PAC 模式
- 守卫模式与持续时间
- Bypass 列表编辑

#### 4.7.2 Clash

功能：

- Tun 开关与 Tun 设置弹窗

- Allow LAN
- IPv6
- Find Process Mode
- Log Level
- 端口配置与随机端口
- External Controller 开关与高级配置
- Web UI 管理
- Clash Core 查看与切换
- Windows UWP Tool
- 更新 GeoData
- 清理 Fake-IP / DNS 缓存

相关子弹窗能力：

- `TunViewer`：auto-route、strict-route、auto-detect-interface、dns-hijack、mtu
- `ControllerViewer`：host、secret、allow private network、allow origins
- `ClashPortViewer`：mixed-port 等端口配置
- `WebUIViewer`：管理多个 Web UI 项
- `ClashCoreViewer`：查看 core 版本/权限/服务配合状态
- `ServiceViewer`：查看安装状态并管理服务模式
- `NetInfoViewer`：查看网络接口信息

#### 4.7.3 Verge

功能：

- App Log Level
- 语言切换
- 主题模式切换
- 托盘点击行为
- 环境变量复制格式
- 启动页选择
- 启动脚本选择
- Theme 弹窗
- Layout 弹窗
- Misc 弹窗
- Backup 区块
- Hotkeys 弹窗
- Runtime Config 查看
- 打开应用目录/Core 目录/日志目录
- 检查更新
- 打开 DevTools
- 退出应用
- 显示应用版本

Theme 弹窗能力：

- 浅色/深色主题
- 主色、辅色、文本色、状态色
- 字体
- CSS 注入

Layout 弹窗能力：

- 系统标题栏
- 保持 Dock 中可见
- 保持 UI Active
- 流量图开关
- 内存占用开关
- 代理分组图标开关
- 菜单图标风格
- 托盘开关
- 托盘图标风格

Misc 弹窗能力：

Hotkeys 弹窗能力：

Backup 区块能力：

- 查看备份文件

- WebDAV 账号信息保存与文件浏览

设计重点：

- 这是当前最需要做信息分组重构的页面
- 现在是“设置列表 + 多弹窗”的组织方式，功能完整，但导航深度和发现成本偏高

## 5. 全局状态与数据入口

主要状态中心：

- `useVergeStore`
  - 管理语言、主题、布局、托盘、快捷键、启动页、备份配置等应用级设置
- `useProfilesStore`
  - 管理当前 profile、profile 列表、全局 chain、chain 日志、激活状态
- `useConnectionsStore`
  - 管理连接页表格布局、排序、列宽、列顺序
- `useRulesStateStore`
  - 管理规则列表、payload、展开状态

数据流特征：

- UI 与 Tauri command/API 耦合较深
- 很多操作是“前端设置状态 + 立即调用后端 + 成功后刷新”
- 多个页面包含实时数据：流量、内存、日志、连接、规则

对重设计的影响：

- 需要预留更多异步态：加载中、刷新中、激活中、校验中、失败回退
- 设计稿不能只画静态成功态

## 6. 当前界面的产品特征总结

该前端不是普通内容型应用，而是：

- 桌面代理控制台
- 配置资源管理器
- 实时监控面板
- 调试/运维工具集合

因此它天然具备这些界面属性：

- 高频切换与即时反馈
- 技术字段多
- 状态可逆性要求高
- 列表/表格/日志/配置编辑器并存
- 弹窗和二级设置非常多

## 7. UI 重设计时应重点解决的问题

### 7.1 信息层级不够稳定

当前多个页面同时承载“浏览 + 编辑 + 执行 + 调试”。

建议优先明确：

- 哪些页面是“控制台”
- 哪些页面是“资源库”
- 哪些页面是“设置中心”
- 哪些页面是“诊断工具”

### 7.2 设置页复杂度过高

建议重设计方向：

- 将 `System / Clash / Verge` 做成更清晰的二级导航
- 减少“列表项点开弹窗”的碎片化操作
- 把高频设置放前、低频设置折叠

### 7.3 订阅与增强链混杂

建议重设计方向：

- 将普通 profile 与 merge/script chain 明确分区
- 强化“当前激活链路”的可视化
- 把“导入、编辑、编排、调试”拆成更顺手的流程

### 7.4 代理页功能密度高

建议重设计方向：

- 提升分组导航与当前选中节点的可见性
- 让延迟测试、筛选、排序更接近“工具条”而非散落图标
- 考虑引入更强的详情侧栏或 inspector

### 7.5 全局状态值得被看见

例如：

- 当前模式
- 系统代理状态
- Tun 状态
- 服务状态
- 更新状态
- 流量与内存

这些内容现在分散在侧边栏、设置页、托盘和局部按钮中，可以在新 UI 里整合成更统一的状态层。

## 8. 重设计优先级建议

建议按以下顺序推进：

1. 先重做全局框架：导航、标题区、状态区、页面容器规范
2. 其次重做代理页：它是最高频的核心工作台
3. 再重做订阅页：它决定配置管理体验
4. 再整理设置中心：降低配置复杂度
5. 最后统一连接/规则/日志/测试等工具型页面的视觉系统

## 10. 结论

这个前端的本质不是单一页面重绘，而是桌面代理工具的完整工作台重构。最重要的不是“换皮”，而是重新组织高频操作、实时状态、配置编辑和诊断工具之间的关系。若要继续推进，下一步最适合输出的是：

1. 一版新的信息架构草图
2. 一版页面优先级矩阵
3. 代理页/订阅页/设置页的详细重设计方案
